# Questie-Octo — Deferred Quest Progression Resolution Audit

**Audit date:** 2026-09-23  
**Baseline audited:** Questie-Octo 1.40  
**Scope:** every one of the 329 quest-chain relations left deferred by the 1.40 multi-source audit

## Executive result

The 329 records did not all have the same kind of uncertainty. The earlier projection was intentionally conservative because it was deciding which links were safe to **walk recursively** when a player skipped multiple quest steps. A second audit of the quest server code establishes a narrower rule: `NextQuestInChain` itself is an **immediate one-step availability lock**. The supplied Tortoise core rejects the earlier quest when its immediate successor is currently active/incomplete or complete; the recursive further-chain check is present in source but disabled/commented out.

That distinction resolves almost the entire deferred set without flattening branches or alternatives.

| Resolution | Count | Runtime treatment |
|---|---:|---|
| Corroborated immediate-only relation | 323 | Added to a separate one-step visibility table; never recursively traversed |
| Already covered by authored `nextChain` | 1 | Kept as-is |
| Disabled quest relation | 2 | Archive only; no normal marker to fix |
| Cross-source contradiction | 2 | Rejected / fail closed |
| Successor missing from loaded snapshot/runtime | 1 | Archive only / fail closed |

**All 329 records are therefore classified. None remain in a generic “we have not looked at it” bucket.**

## Evidence used

- Questie-Octo 1.40 runtime quest data, progression code, and the 1.40 per-source evidence matrix.
- Supplied Turtle/Tortoise `quest_template` snapshot and database-update files.
- Supplied Tortoise core `Player.cpp`, especially `SatisfyQuestNextChain()` and quest reward status handling.
- Questie 5.2.3 and Questie 6.0.0 quest databases.
- pfQuest ClassicAPI and pfQuest Turtle quest databases.
- Public Turtle database pages and historical references for the small set where sources materially disagreed.
- Player reports remain higher priority than these offline references if live behavior differs.

## Server-semantics finding

The key server-side behavior is narrower than Questie-Octo’s skip-ahead enhancement:

1. If a quest has no `NextQuestInChain`, this particular check does nothing.
2. If the immediate successor is active/incomplete or complete, the earlier quest is not takeable.
3. The core does **not** recursively follow the successor’s successor in this check; that recursive call is disabled.
4. A server-repeatable successor returns to `NONE` when rewarded. Its old reward history must therefore not become a permanent immediate-chain lock once it is inactive.

This means branch, exclusivity, event, and resettable metadata are valid reasons to reject **recursive inference**, but they are not automatically reasons to discard a corroborated immediate `NextQuestInChain` visibility rule.

## Runtime design selected

Questie-Octo keeps two deliberately different datasets:

- `Data/QuestProgression.lua`: the existing 1,487 strict linear links. These may be walked forward to infer that an earlier skipped quest is obsolete after a later verified step.
- `Data/QuestDirectProgression.lua`: 323 additional corroborated links from this audit. These are checked **once**, against the immediate successor only, and are never traversed recursively.

The direct table does not mark skipped quests complete, does not modify the Quest Log or server state, does not add polling/`OnUpdate`, and does not issue hundreds of new direct completion-flag API queries. It uses the existing active-quest and completion caches.

## Important rejected cases

### 1083 → 1084 — Enraged Spirits → Wounded Ancients

This SQL forward edge is rejected. None of Questie 5.2.3, Questie 6.0.0, pfQuest ClassicAPI, or pfQuest Turtle corroborates it as a dependency; all four associate Wounded Ancients with Kaela’s Update (1091). The indexed Turtle database for Kaela’s Update likewise lists **both Enraged Spirits and Wounded Ancients as quests opened from 1091**, making them parallel steps rather than a safe 1083 → 1084 availability lock.

### 41388 → 41389 — Wisdom From Failure → Proof

This SQL forward edge is also rejected. The indexed Turtle database series explicitly places **41393 — The Strength To Move Mountains** between Wisdom From Failure and Proof. The server source tree itself contains the 41393 quest row in a database update, while a later update writes a direct 41388 → 41389 relation. Because those sources conflict, Questie-Octo fails closed instead of copying the later SQL field.

### 40749 → 40750 — Translating The Unknown → missing successor

The supplied base quest snapshot/runtime does not contain quest 40750. The relation is archived, but no visibility rule is generated. The server loader itself clears an invalid next-chain reference when its target quest is absent, so inventing the missing target would be indefensible.

## Repeatable/resettable behavior

Eight generated immediate relations point at successors marked server-repeatable. They suppress the earlier quest while the successor is actively in the Quest Log, but an old inactive completion is not treated as a permanent lock. Yearly/daily state continues to use Questie-Octo’s existing current-reset lock rather than raw historical completion.

## Criticism-resistant boundary

This audit intentionally does **not** claim that every relation is a single linear quest chain. That would be false. The 323 newly usable records are only claims about immediate availability supported by the supplied server semantics and at least one additional quest-data reference. Recursive skip-ahead inference remains restricted to the original 1,487 strict links plus separately authored cases.
