0.1.35 SCALE HOTFIX 2 - ACE3V RANGE RELEASE
---------------------------------------------
User diagnostics proved the semantic scale and frame resize path worked while

after release.

Questie's supplied AceGUI/AceConfig range flow was compared again across
5.2.3, 6.0.0, 3.3.5, 7.0.0 and 8.0.0. Questie commits range changes through
OnValueChanged and refreshes the AceConfig dialog on OnMouseUp.

Ace3v adapts that callback ABI for Lua 5.0 with an explicit argc slot. On the

  OnMouseUp      -> refresh AceConfigDialog only; no second setting write

unchanged.

0.1.35 TURN-IN HOTFIX - QUESTIE COMPLETE '?' + ACE3V ONUPDATE
-------------------------------------------------------------
Questie trace (5.2.3 -> 6.0.0 -> 3.3.5 -> 7.0.0 -> 8.0.0) found:

1. Questie creates separate frames for available and completed quest icons.
   Questie-Octo incorrectly merged exact-role descriptors by source+coordinate,
   causing an available ! to hide a completed ?.

2. Questie deliberately renders available icons at OVERLAY sublevel 5 and
   completed icons at OVERLAY sublevel 6. Completed ? therefore stays visible
   above an overlapping available !.

3. Questie 6 falls back to IsQuestComplete(questId) when the quest-log
   isComplete field is unavailable. Questie-Octo now uses that legacy fallback
   and no longer treats numeric -1 (failed) as complete merely because Lua
   considers it truthy.

4. Ace3v AceConfigDialog RefreshOnUpdate used a modern self-argument style.
   Vanilla 1.12 supplies frame-script context through global `this`, causing
   line 1722 to index nil during refresh. The compatibility layer now consumes
   Vanilla's global this without changing Questie's AceConfig architecture.

No marker displacement was added. Exact Questie icons are allowed to overlap.


0.1.35 TURN-IN HOTFIX 2 - QUESTIE 3.3.5 QUEST-LOG COMPAT
----------------------------------------------------------
The previous turn-in visual fix removed exact-marker merging, but user testing
still showed no yellow completed-quest marker.

The Questie 3.3.5 compatibility bridge exposed the actual root cause:
raw old/Turtle GetQuestLogTitle has a legacy suggestedGroup return before
isHeader, so isHeader/isCollapsed/isComplete are shifted by one position.

Questie-Octo now normalizes GetQuestLogTitle at ClassicAPI, following Questie
3.3.5. It also passes questLogIndex into the legacy GetQuestObjectives bridge.

Map, minimap, turn-in texture, exact-marker layering, and scale behavior were
not redesigned in this hotfix.

0.1.37 ALPHA - MINIMAP PROJECTION FIX
--------------------------------------
FULL BACKPORT RECHECK
---------------------
Questie minimap architecture was rechecked through the approved chain:
  Questie 5.2.3 -> 6.0.0 -> 3.3.5 -> 7.0.0 -> 8.0.0

Those Questie versions use HereBeDragons/world-coordinate projection on newer
clients. Turtle/Vanilla 1.12 does not provide that library, so pfQuest remains
the permitted final compatibility reference for the projection itself.

ROOT CAUSE
----------
Questie-Octo's initial pfQuest MinimapIndoor() adaptation inverted pfQuest's
state mapping.

pfQuest behavior:
  state 0 -> MINIMAP_ZOOM[0] -> 300-yard family
  state 1 -> MINIMAP_ZOOM[1] -> 466.67-yard family

When current minimap zoom is NOT minimapInsideZoom, pfQuest returns state 1.
Questie-Octo incorrectly returned 0. That selected a 300-yard span where
pfQuest selected 466.67 yards, making projected quest-marker movement about
1.56x too large as the player moved away from the target.

0.1.37 copies pfQuest's Vanilla minimap indoor/zoom-state logic exactly,
including its temporary zoom probe and its original state mapping.

This build starts from the plain audited 0.1.36 turn-in build. None of the
experimental native-yellow-circle backing textures or minimap-frame scanners
are included.

Retained:
  * audited objective-less completion / yellow turn-in '?' state
  * Questie AceConfig/AceGUI options and Ace3v Lua 5.0 compatibility
  * map/minimap icon scaling
  * quest accept/remove lifecycle fixes
  * item-start markers / rare static respawn tooltips
  * canonical marker coordinates (no displacement)

1.0.81 - SHARED CALLBACKHANDLER ISOLATION / SPY COMPATIBILITY
-------------------------------------------------------------
A supplied Spy 4.5.0 archive exposed that Questie-Octo's Lua-5.0
CallbackHandler translation was registered globally as `CallbackHandler-1.0`
minor 6.  When Questie-Octo loaded first, LibStub caused Spy's same-minor
CallbackHandler to be skipped.  Spy then inherited Questie-Octo's callback
runtime even though Spy's Ace3v libraries use the Vanilla explicit-argc ABI
`Fire(eventName, argc, ...)`.

The old development note stating that CallbackHandler behavior was retained was
therefore too broad: the Lua syntax conversion worked for Questie-Octo's option
path, but its `Fire` entry point did not preserve Ace3v's explicit argc slot.

Compatibility correction:
  * Questie-Octo's handler is now private: `QuestieOcto-CallbackHandler-1.0`.
  * Questie-Octo AceConfigRegistry explicitly uses the private handler.
  * The private handler uses the Ace3v explicit-argc `Fire` contract.
  * Questie-Octo no longer claims the global `CallbackHandler-1.0` library, so
    unrelated addons can load their own copy without load-order interference.

No Spy files are modified or bundled by Questie-Octo.

1.0.95 - FINALIZE WRAPPED TILDE AFTER TOOLTIP LAYOUT
-------------------------------------------------------
In-game 1.0.94 testing showed the ranged item-start tilde could still land
between visual rows. The problem was timing rather than the ARIALN glyph: the
marker position was calculated immediately after AddLine(), before GameTooltip
had finalized wrapping. At that point the FontString could still report a
single-row height, then become two rows only when Show() laid the tooltip out.

positioning pass immediately after tooltip:Show(), when the real wrapped height
is available. Single-line rare respawn placement is unchanged. Final wrapped
rows anchor the ARIALN tilde to the center of the first visual row. No tooltip
wording, respawn values, drop rates, or thresholds changed.

1.0.91 - QUEST LOG TRANSACTION / STALE-INDEX SAFETY
------------------------------------------------------------
- Full-project audit following independent player reports of apparently unrelated
  Mulgore, Ragefire Chasm, and Durotar quests/objectives disappearing. The named
  quest records, compiled runtime database, and map candidate index were checked
  before changing code; no broad missing-quest/database defect was found.
- Confirmed a systemic race in Quest/QuestLog.lua: Refresh() snapshots the native
  Quest Log entry count and scans GetQuestLogTitle()-style numeric indices across
  multiple scheduler frames. Native header collapse/expand and quest add/remove
  operations can reindex that list while the old scan is still in progress. A
  second refresh was queued, but the old partial scan could publish first, creating
  one active snapshot assembled from two different native layouts.
- Added an unpublished scan generation guard. Any new Quest Log refresh request
  received while a scan is running invalidates that generation immediately. The
  next continuation discards its local replacement state and queues a fresh pass;
  an invalidated scan never publishes QUEST_LOG_CHANGED/active/map state. This is
  event-driven replacement work only and adds no polling/OnUpdate/background scan.
- Synthetic regression using the real QuestLog.lua reproduces the old failure: an
  expanded-layout first batch followed by a header collapse publishes an incomplete
  active set in 1.0.90. With 1.0.91, the stale continuation is aborted, the previous
  authoritative state remains published, and the replacement scan recovers the full
  active set while preserving collapsed-header presentation state.
- Audited every other runtime consumer of cached Quest Log indices. Timed quests
  already validate/re-resolve their live index by quest ID. Tracker Open/Show in
  Quest Log now applies the same fail-closed validation before selecting a row.
- Kept 1.0.83 Hide Completed Objectives semantics unchanged. The rejected 1.0.87
  scroll-anchor, 1.0.88 cross-cache merge, and 1.0.89 completion override remain
  absent. No individual quest-data override was added for the player reports.
- Rite of Vision (772) remains a separately documented objective-free/scripted
  semantic edge case; no unsafe global IR rule change was made. A Dryad's Gratitude
  (40587) remains correctly marked timed in the compiled data; no speculative map
  objective was fabricated for its courier item.
